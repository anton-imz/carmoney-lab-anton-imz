# intent_MILEAGE — пробег больше 400 000 км → решение review

Собрано по итогам интервью Grill Me; лог вопросов и ответов —
`docs/intent/grill_MILEAGE.md`. Источники в пунктах: «ответ в интервью»
или «код: <файл>».

## Замысел

В расчёт решения по заявке добавляется проверка пробега авто: при пробеге
строго больше 400 000 км решение понижается до review («ответ в интервью» —
исходная формулировка задачи). До правила решение вычислялось только из LTV
(код: backend/src/Domain/DecisionEngine.php). Правило уже действует в коде —
intent фиксирует замысел ретроспективно
(код: backend/src/Domain/AssessmentService.php).

## Зачем

Пробег влиял только на приём заявки, но не на решение: решение вычислялось
из одного LTV, без учёта пробега (код: backend/src/Domain/DecisionEngine.php,
backend/src/Domain/ApplicationValidator.php). Правило делает пробег фактором
расчёта решения. Какую проблему это решает для бизнеса — в интервью не
прозвучало, вынесено в Open questions.

## Constraints

- Порог 400 000 км, граница включительная: при 400 000 правило не
  срабатывает, срабатывает при пробеге строго больше порога
  («ответ в интервью» — формулировка «не больше 400 000 км»;
  код: backend/config/rules.php, backend/src/Domain/AssessmentService.php).
- Правило понижает только approve → review; решения review и reject не
  меняются, reject при пробеге выше порога остаётся reject
  («ответ в интервью» — вопрос 1; код: backend/src/Domain/AssessmentService.php).
- Правило сочетается с решением по LTV: approve / review / reject
  вычисляются по порогам LTV 60% и 85% (код: backend/config/rules.php,
  backend/src/Domain/DecisionEngine.php).
- Приём заявки не меняется: к расчёту принимается пробег 0–500 000 км;
  вне диапазона или неуказанный пробег — заявка не принимается к расчёту
  (ошибка данных), это не решение review/reject
  (код: backend/src/Domain/ApplicationValidator.php,
  backend/config/rules.php).
- Заявка, пониженная до review, получает лимит 0 — как любое решение,
  кроме approve (код: backend/src/Domain/AssessmentService.php).
- Порог — бизнес-число в справочнике правил; код читает значение из
  справочника, а не хранит его у себя (код: backend/config/rules.php).

## Open questions

- Бизнес-мотивация: какую проблему для бизнеса решает учёт пробега и чем
  обусловлен порог 400 000 км. В интервью не прозвучала; в коде есть только
  пометка, что числа учебные и синтетические
  (код: backend/config/rules.php). Статус: открыт.
- Сверка с исходной формулировкой: «иначе решение review» буквально допускает
  чтение «при пробеге выше порога решение всегда review». Подтверждённая в
  интервью семантика — понижение только approve, reject остаётся reject.
  Статус: закрыт — заказчик, ответ в интервью (вопрос 1, лог
  `grill_MILEAGE.md`).

## Не входит

- Починка пустой строки пробега: пустая строка нормализуется в 0 и проходит
  приём — существующая нормализация числовых полей; при необходимости чинить
  отдельной задачей («ответ в интервью» — вопрос 2;
  код: backend/src/Domain/ApplicationValidator.php).
- Изменение проверки приёма заявки по пробегу (диапазон 0–500 000,
  отсутствие/null): правило меняет только расчёт решения («ответ в
  интервью» — формулировка «в расчёт решения по заявке»;
  код: backend/src/Domain/ApplicationValidator.php).
- Расчёт лимита по возрасту авто — отдельная задача LOAN-12
  (код: backend/src/Domain/AssessmentService.php, backend/config/rules.php).
