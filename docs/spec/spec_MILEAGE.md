# spec_MILEAGE — пробег больше 400 000 км → решение review

Спецификация по `docs/intent/intent_MILEAGE.md` (интервью Grill Me, лог
`docs/intent/grill_MILEAGE.md`). Источники у каждого числа: «ответ в интервью»
или «код: <файл>». Спека не добавляет требований, которых не было в intent.

## Входит

- REQ-MILEAGE-01: правило «пробег строго больше 400 000 км понижает решение
  approve до review» в расчёте решения по заявке.
- REQ-MILEAGE-02: приоритет правила относительно решений по LTV
  (review/reject не понижаются и не повышаются).
- REQ-MILEAGE-03: чтение порога из справочника бизнес-правил.
- REQ-MILEAGE-04: лимит 0 у заявки, пониженной до review.

## Не входит

- Починка пустой строки пробега: пустая строка нормализуется в 0 и проходит
  приём — существующая нормализация числовых полей; при необходимости чинить
  отдельной задачей (ответ в интервью — вопрос 2;
  код: backend/src/Domain/ApplicationValidator.php).
- Изменение проверки приёма заявки по пробегу (диапазон 0–500 000 км,
  отсутствие/null → ошибка данных, не решение): правило меняет только расчёт
  решения (ответ в интервью; код: backend/src/Domain/ApplicationValidator.php).
- Расчёт лимита по возрасту авто — отдельная задача LOAN-12
  (код: backend/src/Domain/AssessmentService.php, backend/config/rules.php).

## Требования

### REQ-MILEAGE-01 — порог понижения решения

При пробеге **строго больше** 400 000 км решение по заявке, вычисленное как
approve по LTV, понижается до review. При пробеге 400 000 км правило не
срабатывает (граница включительная).

Источник порога 400 000 км: ответ в интервью («не больше 400 000 км»);
код: backend/config/rules.php (`vehicle.review_mileage_km => 400000`),
backend/src/Domain/AssessmentService.php.

**AC-MILEAGE-01** (REQ-MILEAGE-01, REQ-MILEAGE-02):
- Given заявка с LTV ≤ 60% (решение по LTV — approve; пороги LTV: код:
  backend/config/rules.php `ltv.approve_max => 60.0`) и пробегом 399 999 км
  (внутри допустимого диапазона приёма 0–500 000; код: backend/config/rules.php
  `vehicle.max_mileage_km => 500000`) — When расчёт решения — Then решение
  `approve`, правило не сработало.
- Given та же заявка с пробегом ровно 400 000 км — When расчёт решения —
  Then решение `approve`: порог включительный, при 400 000 правило не
  срабатывает.
- Given та же заявка с пробегом 400 001 км — When расчёт решения — Then
  решение `review`.

### REQ-MILEAGE-02 — правило понижает только approve

Правило понижает только approve → review. Решения review и reject по LTV
пробег не меняет: reject при пробеге выше порога остаётся reject.

Источник: ответ в интервью — вопрос 1; код: backend/src/Domain/AssessmentService.php.

**AC-MILEAGE-02** (REQ-MILEAGE-02):
- Given заявка с LTV > 85% (решение по LTV — reject; порог: код:
  backend/config/rules.php `ltv.review_max => 85.0`) и пробегом 400 001 км —
  When расчёт решения — Then решение `reject` (не review).
- Given заявка с 60% < LTV ≤ 85% (решение по LTV — review) и пробегом
  400 001 км — When расчёт решения — Then решение `review` (без изменений).

### REQ-MILEAGE-03 — порог в справочнике правил

Порог 400 000 км — бизнес-число в справочнике правил (`vehicle.review_mileage_km`).
Код читает значение из справочника и не хранит его у себя: смена порога в
справочнике меняет поведение без правки кода.

Источник: код: backend/config/rules.php, backend/src/Domain/AssessmentService.php.

**AC-MILEAGE-03** (REQ-MILEAGE-03):
- Given справочник с `vehicle.review_mileage_km = 399999` — When расчёт по
  заявке с approve по LTV и пробегом 400 000 км — Then решение `review`.
- Given справочник с `vehicle.review_mileage_km = 400001` — When расчёт той же
  заявки с пробегом 400 000 км — Then решение `approve`.

### REQ-MILEAGE-04 — лимит у пониженной заявки

Заявка, пониженная до review по пробегу, получает лимит 0 — как любое решение
кроме approve.

Источник: код: backend/src/Domain/AssessmentService.php.

**AC-MILEAGE-04** (REQ-MILEAGE-04):
- Given заявка с approve по LTV и пробегом 400 001 км (понижена до review
  правилом REQ-MILEAGE-01) — When расчёт — Then `approved_limit = 0`.

### REQ-MILEAGE-05 — приём заявки не меняется

Приём заявки по пробегу остаётся прежним: к расчёту принимается пробег
0–500 000 км; вне диапазона или неуказанный пробег — заявка не принимается к
расчёту (ошибка данных), это не решение review/reject. Пустая строка пробега
нормализуется в 0 и проходит приём.

Источники: диапазон 0–500 000 — код: backend/config/rules.php
(`vehicle.max_mileage_km => 500000`); поведение при пустой строке — ответ в
интервью, вопрос 2; код: backend/src/Domain/ApplicationValidator.php.

**AC-MILEAGE-05** (REQ-MILEAGE-05):
- Given заявка с пробегом 500 000 км — When приём заявки — Then заявка
  принята к расчёту (верхняя граница диапазона включается).
- Given заявка с пробегом 500 001 км — When приём заявки — Then заявка не
  принята: ошибка данных («Пробег от 0 до 500000 км»), не решение review/reject.
- Given заявка без поля `mileage` (неизвестный пробег) — When приём заявки —
  Then заявка не принята: ошибка данных, не решение review/reject.
- Given заявка с пустой строкой `mileage: ""` — When приём заявки — Then
  заявка принята, пробег нормализован в 0; при LTV ≤ 60% решение `approve`
  (0 ≤ 400 000).

## Open questions из intent

- Бизнес-мотивация учёта пробега и порога 400 000 км: в интервью не
  прозвучала, в коде только пометка об учебных синтетических числах
  (код: backend/config/rules.php). Статус: **открыт** — мотивация не получена,
  в спеку не входит, поведение зафиксировано по подтверждённой формулировке
  (ответ в интервью). Числа учебные, уточнение мотивации не блокирует спеку.
- Сверка с исходной формулировкой «иначе решение review» (возможное чтение
  «при пробеге выше порога решение всегда review»): подтверждена семантика
  «понижение только approve, reject остаётся reject». Статус: **закрыт** —
  ответ заказчика в интервью, вопрос 1, лог `grill_MILEAGE.md`;
  зафиксировано в REQ-MILEAGE-02.
